# timesnow 路线图

这份路线图把[设计愿景](vision.md)里"还没有的"排成顺序。
每一阶段回答一个问题：**做完它，引擎多会一件什么事。**

排列依据只有一条：**先让"渲染不将就"这个前提能被验证。**
叙事层已经完整了（对话、分支、变量、存读档、回看历史、热重载），
而引擎存在的理由——Ren'Py 给不了的效果——一个都还没有。
如果一部短篇做完了却用不上任何新东西，那才是最坏的结果：
引擎长得像 Ren'Py，却没有 Ren'Py 的成熟度。

```
阶段 0  证明叙事层能用            ████████░░  进行中
阶段 1  动画与动态场景            ░░░░░░░░░░  未开始   ← 关键路径
阶段 2  表现力深水区              ░░░░░░░░░░  未开始
阶段 3  开发体验产品化            ░░░░░░░░░░  未开始
```

## 阶段 0：证明叙事层能用

**目标：** 一部做完的、能拿出去给人玩的短篇，里面**至少用到一个 Ren'Py 做不到的效果**。

**现状：** `examples/phone` 已经 10 章 4 个结局，`--check` 干净、没有悬空引用。
缺的是收尾——ch3 被删掉过、`ch8` 挤在 `ch7.tsn` 里，以及一部作品需要的最后打磨。

**为什么排第一：** 叙事层是唯一已经完整的一层，但它只被一份**没做完**的示例用过。
没人从头玩到尾，就没人知道它到底缺什么。

**"做完了"的标志：**

- 从头玩到任意一个结局，中途存读档、翻回看历史都不出戏
- 至少一处用上阶段 1 的动画（所以这一阶段**跨到阶段 1 之后才算真完**）

**这一阶段会冒出来的东西：** 无法预测，而且**这正是它的价值**。
前几轮的证据很一致——真实数据会抓出测试抓不到的问题
（v1 存档读不出来那个 bug 就是这么被抓到的）。

## 阶段 1：动画与动态场景 ← 关键路径

**目标：** 立绘和场景能**随时间变化**。这是"实时立绘、动态场景"的最小地基。

**好消息：地基都在。** 核实过了：

| 需要的东西 | 现在有没有 |
|---|---|
| 每帧喂立绘位置 | ✅ `set_characters(&[(name, Rect)])` |
| 每帧的驱动钩子 | ✅ `Script::update(dt)`，和打字机、`@fade` 共用 |
| 要补间的字段 | ✅ `StageRect { x, y, w, h }` |
| 透明度 | ✅ 全局 alpha 一条通道 |
| 着色 | ✅ shader 里 `params.yzw` 做 tint |
| 渲染层测试 | ✅ 21 项（纯函数部分） |

**所以这是加在现成结构上的一个纯数值模块，不是重写渲染器。**

### 1.1 补间引擎（先做，因为它是纯的）

- **是什么：** 关键帧 + 缓动。给一个属性一串 `(时间, 值)` 和一条缓动曲线，
  在任意 `t` 求出当前值
- **放哪：** `vm.rs` 旁边一个 `tween.rs`。**不碰 GPU、不碰窗口、不碰 `Instant`**——
  时间由调用方传进来（和 `Vm` 同一条设计线）
- **为什么先做：** 它是纯函数，可以完全单测。动画最容易出的错
  （缓动端点不精确、时长 0 卡住、关键帧无序）全都能在这一层钉住，
  不用等画到屏幕上才发现
- **完成标准：** 缓动覆盖 `linear` / `ease_in` / `ease_out` / `ease_in_out`；
  `t=0` 和 `t=1` 必须精确落在首尾关键帧上（浮点累积误差不能让它差一点）；
  时长 0 直接到终点；单向推进不回头

### 1.2 DSL：`@move` / `@anim`

- **是什么：** 让剧本作者能写动画。最小可用的一种：

```
@move alice to 0.749 0.25 0.211 0.75 over 0.6 ease_out
@fade alice to 0.0 over 1.0
```

- **为什么从 `@move` 起步：** 它是"立绘从 A 移到 B"，最常用、最容易解释、
  也最容易做对。复杂的关键帧序列可以等这一条被真用过再说
- **完成标准：** 动画期间 `is_animating()` 为真（否则静止画面不会重绘）；
  动画中的立绘**能被正确存档**（存的是终态还是当前值？这个决定要写进文档）；
  `@move` 期间点击不该打断它（和 `@wait` 一致）

### 1.3 shader 参数挂钩

- **是什么：** 让剧本能设 shader 里的几个通用 uniform。现在只有一个 tint；
  扩成一组具名参数，剧本可以 `@shader alice wave=0.5` 这样用
- **为什么值得做：** 这是"shader 驱动的风格"的入口。它不需要作者写 shader——
  引擎提供几种内置效果参数，剧本调数值
- **完成标准：** 参数变化能参与补间（和 1.1 共用）；
  没有 shader 的立绘不受影响

**这一阶段的退出条件：** 能用 `@move` 做出一段**能拿给人看的**立绘动画，
并且它出现在阶段 0 那部短篇里。

**风险（说实话）：**
- **存档语义是这里最难的决定。** 存档时正好有一半播完的动画，存什么？
  两个合理选项：存目标态（读档后动画从头播）或存当前值（读档后停在半路）。
  我倾向**存目标态**——读档后画面是"完成的样子"，比停在半路可预期
- 动画一多，**重绘判定**就要重新想：现在 `is_animating()` 只看打字机和淡入淡出

## 阶段 2：表现力深水区

阶段 1 做完，立绘能动了。这一阶段做真正区分"现代 GPU"的东西。
**每一项都需要单独设计，不是一个任务。**

- **2.1 骨骼 / 网格形变** —— 让立绘能呼吸、转头、被风吹。
  这是 Live2D 那一类的活儿，也是"实时立绘"真正的意思。
  需要网格细分 + 骨骼权重，是这一层里最贵的一项
- **2.2 后处理链** —— 全屏效果：bloom、色差、畸变、色调映射。
  需要离屏渲染 + 一个 pass 链。做完之后"整屏氛围随剧情变化"才成立
- **2.3 状态管理** —— 现在是全局变量 + `@if`。
  复杂状态要么给 DSL 加集合类型，要么在宿主层用 Rust 写，
  通过参数喂给 shader（2.1 和 2.2 都需要这个）

**进入条件：** 阶段 1 的那部短篇里，动画已经被真用过，并且知道下一步缺什么。
**不建议提前做**——这三项每一项都能吃掉大量时间，而没有真实需求的话，
做出来的接口大概率是错的。

## 阶段 3：开发体验产品化

到这一步引擎本身够用了，补的是"让别人也能用"的东西。

- **3.1 WASM 预览** —— 浏览器里跑，为了分享和快速看效果
- **3.2 项目脚手架（轨道 B）** —— 让不写 Rust 的人上手。
  这是[愿景](vision.md)里那条双轨制的另一半
- **3.3 插件接口（玩法层）** —— 需要先想清楚：插件能碰什么、不能碰什么，
  以及它怎么和存档格式共存。**这一个问题的难度被低估过**
- **3.4 剧情流程图** —— 哪些块通向哪些结局。已有的可达性检查是它的地基
- **3.5 可视化编辑器** —— 独立产品，不是这个引擎的一个功能

## 不排进路线图的事

见[愿景里的"刻意不做的事"](vision.md#刻意不做的事)。
3D、物理、网络、通用 UI 框架——这些不在规划里，也不会被"宽边界"背书进来。

## 这份路线图会过期

上面每个阶段的"完成标准"都是**现在**能写出来的最好猜想。
阶段 0 的真实目的就是用一部真作品去证伪它们——
如果做完短篇发现最缺的是别的，那这份路线图就该改。

**改它不算失败，把它当合同才是。**
